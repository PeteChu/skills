How file uploads work in acme-docs

Prompt I need to let people attach PDFs to comments. Before I touch anything: how do uploads actually work in this repo, end to end, and what's the minimum I have to add for a new kind of upload?

TL;DR

  • Files never pass through our API. The browser asks for a presigned URL, then uploads straight to the bucket.
  • A bucket event triggers the virus scanner; only after it passes does the file get a row in attachments and become visible.
  • Each upload kind (avatar, attachment, import) is declared in config/uploads.yaml. A new kind is one YAML entry plus one route.

Step by step

Steps 1–2 run in the user's tab; 3–4 run asynchronously, usually within 10 seconds. The comment shows a "scanning" chip until step 4 lands.

useUpload posts the file's name, size and MIME type. The API looks up the upload kind in uploads.yaml, rejects anything over max_bytes or outside mime, inserts a pending_uploads row, and returns a URL that is valid for 15 minutes and only for that exact key and size.

// api/uploads/presign.ts
const key = `${kind}/${orgId}/${nanoid()}`;
const url = await s3.presignPut(BUCKET, key, {
  contentLength: body.size,       // signed: client can't lie later
  contentType: body.mime,
  expiresIn: cfg.ttl_seconds,
});
await db.pendingUploads.insert({ id, key, kind, userId, docId });
p50: 38 msauth: route middleware

The hook PUTs the file to the presigned URL with progress events. Files over 100 MB switch to multipart: the hook asks for part URLs in batches of 20 and uploads 4 parts in parallel. Our servers never see the bytes, so API memory and timeouts do not limit file size.

If the tab closes mid-upload the pending_uploads row expires after 24 h and a bucket lifecycle rule removes orphaned parts.

ObjectCreated events go to the upload-scan queue. The worker streams the object through ClamAV and, for images, strips EXIF and renders the variants listed for that kind. Nothing is user-visible yet.

// workers/scan/index.ts
const verdict = await clam.scanStream(s3.stream(evt.key));
if (verdict.infected) {
  await s3.move(evt.key, `quarantine/${evt.key}`);
  return api.finalize(id, { status: 'quarantined', sig: verdict.name });
}
return api.finalize(id, { status: 'clean', variants: await render(evt) });

Finalize is an internal route (mTLS only). It moves the pending_uploads row into attachments, then publishes upload.ready on the doc's realtime channel, which swaps the "scanning" chip for the file card. This is the only place an attachments row is created.

The bucket is private. When a doc renders, the API checks doc access and signs a files.acme.dev URL valid for 15 minutes. The editor refreshes URLs on focus, so a tab left open overnight does not show broken images.

03

Adding PDF attachments to comments

You don't touch the presign, scan or finalize code. Declare a kind, mount one route, and call the hook. Use ← → to switch tabs.

# config/uploads.yaml
defaults:
  ttl_seconds: 900          # presigned URL lifetime
  scan: required
kinds:
  avatar:
    max_bytes: 2097152      # 2 MB
    mime: [image/png, image/jpeg, image/webp]
    variants: [64, 256]
  comment_pdf:
    max_bytes: 26214400     # 25 MB, single PUT
    mime: [application/pdf]
    variants: [thumb_page_1]
// api/routes/comments.ts
router.post(
  '/docs/:docId/comments/:commentId/attachments',
  requireDocAccess('comment'),
  presignUpload('comment_pdf'),   // reads kinds.comment_pdf
);
// web/comments/AttachButton.tsx
const { start, progress, status } = useUpload('comment_pdf', { docId, commentId });

return (
  <FilePicker accept="application/pdf" onPick={start}>
    {status === 'scanning' ? <Chip>Scanning…</Chip> : <Progress value={progress} />}
  </FilePicker>
);

Shortcut

If the generic attachment kind (any MIME, 2 GB) is acceptable, skip the YAML entry and pass 'attachment'. Add a dedicated kind only to restrict MIME types or size, as PDFs-only does here.

04

Gotchas worth knowing

  • Local dev skips the scanner.With SCAN_MODE=off (the default in .env.example) finalize runs inline, so you never see the "scanning" state locally. Set it to stub to get a 3 s fake delay.
  • MIME is checked twice, differently.Presign trusts the browser's claimed type; the scanner sniffs magic bytes. A renamed .exe passes step 1 and is quarantined at step 3.
  • Size is signed into the URL.Re-using an upload ID for a different file fails with a 403 from the bucket, not from our API, so it won't appear in API logs.
  • Deleting a comment doesn't delete files.Attachments are owned by the doc. A nightly job (jobs/gc-attachments.ts) removes unreferenced ones after 30 days.
05

FAQ

Can I show a preview before the scan finishes?

Only from the local File object (an object URL in the uploader's own tab). Other viewers get nothing until finalize, by design.

Where do I see quarantined files?

Admin → Security → Quarantine lists them with the ClamAV signature. Every quarantine also emits upload.quarantined to the security Slack channel.

Do I need a migration for a new kind?

No. attachments.kind is a text column validated against the YAML at boot. Unknown kinds fail the deploy's smoke test, not production traffic.
