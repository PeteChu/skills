#1

Cache the pnpm store

S

.github/workflows/ci.yml:24

Found in the repo: actions/setup-node runs without cache: 'pnpm', so all six jobs download about 1.1 GB of packages from scratch. The lockfile hasn't changed in 82% of runs.

Impact −3.5 min on every job, plus about 6 runner-hours a day. It's a two-line change.

#2

Skip e2e on docs- and config-only PRs

S

.github/workflows/e2e.yml · on.pull_request

Found in the repo: there's no paths filter. In the last 30 days, 22% of PRs touched only docs/**, *.md, or .changeset/, and each one waited the full 21-minute Playwright run.

Impact About −8 min on the average PR. Branch protection needs a no-op "e2e" job so the required check still reports.

#3

Turn on the Turborepo remote cache that's already configured

S

turbo.json · .github/workflows/ci.yml:41

Found in the repo: turbo.json declares correct outputs for all 31 packages, but TURBO_TOKEN is never set in CI, so every run rebuilds every package. Local builds already get 74% cache hits.

Impact About −6 min on the build stage, which is on the critical path. Needs one secret and an env line.

#4

Quarantine the 41 flaky tests instead of retrying everything

M

jest.setup.ts:3 · playwright.config.ts:12

Found in the repo: jest.retryTimes(3) is set globally and Playwright has retries: 2. Run logs show 41 tests that retry in more than 5% of runs. Every other test pays the retry overhead and real failures take 3× as long to report.

Impact About −4 min p50, more at p90. It also attacks the 17% manual re-run rate.

#5

Shard unit tests four ways

M

jest.config.ts · package.json "jest": "^29.7"

Found in the repo: Jest 29 supports --shard=i/n, but the unit job runs 6,200 tests on one runner for 14 minutes. Two suites (billing/ and search/) account for 40% of that, so the shards will need balancing.

Impact Unit stage drops to about 4 min. This only helps wall-clock time once e2e is shorter too (see #6).

#6

Give each Playwright worker its own Postgres schema

M

playwright.config.ts:8 · packages/db/testing/createSchema.ts

Found in the repo: e2e runs with workers: 1 and a comment // TODO: parallelize once DB is isolated. The API integration tests already isolate data with createSchema(workerId). Nobody has wired it into Playwright fixtures.

Impact About −12 min. It's the biggest item on the critical path that doesn't need new infrastructure.

#7

Finish the move to TypeScript project references

L

tsconfig.json · packages/*/tsconfig.json

Found in the repo: typecheck runs tsc --noEmit across the whole repo. 9 of 31 packages already have composite: true from an abandoned migration, but the remaining 22 have circular imports between ui and forms that need untangling first.

Impact About −5 min on typecheck, but typecheck isn't on the critical path. The real benefit is faster editors.

#8

Reorder the API Dockerfile and cache its layers

M

apps/api/Dockerfile:6 · docker/build-push-action

Found in the repo: the Dockerfile runs COPY . . before pnpm install, so any change busts the install layer. The build step also sets no cache-from, so even unchanged layers rebuild.

Impact About −3.5 min, on the critical path. The reorder also speeds up local docker compose up.

#9

Run only the tests affected by the diff

L

turbo run test --filter=...[origin/main]

Found in the repo: Turbo already knows the package graph, so affected filtering is a flag. The risk is the e2e suite, which has no package boundaries. It would need a test-to-route mapping, and e2e/ doesn't have one yet.

Impact About −15 min on the median PR. In exchange, main has to run the full suite and a few breakages will only show up after merge.

#10

Adopt a merge queue and run e2e only there

XL

branch protection · on.merge_group

Found in the repo: PRs wait on the full suite because main has no other safety net. With a merge queue, PR checks become lint, typecheck, and affected unit tests, while e2e runs once per merge group. That changes how the team works, not just the YAML.

Impact PR feedback in about 9 min. It also fixes the real complaint, people merging before checks finish. It needs buy-in from the 6 team leads.

#3 and #6 together shorten the critical path by about 18 minutes and need no new infrastructure. Everything else either sits off the critical path or is a team decision.
