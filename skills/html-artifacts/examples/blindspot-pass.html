01 Landmine

Parcels carry weight in two units, and the adapter you'll copy reads the wrong one

Migration 0087_weight_grams added parcels.weight_g as the source of truth, but a trigger still back-fills the old weight_oz column (rounded to whole ounces) because usps-legacy.ts needs it. ups.ts, the newest and cleanest adapter, reads weight_oz too.

Why it bites DHL rates by 0.5 kg steps. Ounce rounding drifts a 2.24 kg parcel to 2.27 kg and moves it into the next band, so quotes come out up to 12% high on light parcels. No test catches it because fixtures use round numbers.

Prompt fix

Evidence: db/migrations/0087_weight_grams.sql · carriers/ups.ts:41 · db/triggers/parcels_weight_oz.sql

02 Landmine

The rate cache can't tell two carriers apart on the same lane

RateCache keys quotes on origin_zip3 × dest_zip3 × service_level with a 6-hour TTL. That worked while every service level mapped to exactly one carrier. DHL Express and UPS Next Day Air both map to service_level = "express".

Why it bites Whichever carrier is quoted first wins the cache for six hours. Checkout then shows the UPS price on a DHL label, and finance only finds the gap in the monthly carrier reconciliation.

Prompt fix

Evidence: rates/cache.ts:18 · config/service-levels.yaml

03 History

Someone already added a carrier and it was reverted for buying duplicate labels

PR #1932 ("Add FedEx Ground", Jun 2025) was reverted after eight days. When the FedEx API timed out with a 504, the job retried and bought a second label. That added up to 1,140 duplicate labels and about $11.2k in carrier charges. ADR-014 specifies idempotency keys for label purchases, but only ups.ts implements them.

Why it bites Sandbox never returns 504s, so every local and CI test passes. The first slow day at DHL repeats the FedEx incident.

Prompt fix

Evidence: PR #1932 and revert a41c9e2 · docs/adr/014-idempotent-labels.md · labels/purchase.ts:57

04 Missing concept

Cross-border shipments need a customs declaration, and the adapter interface never asks for one

Every Acme carrier so far is domestic except Canada Post, which builds a CommercialInvoice (HS code, origin country, declared value per line) inside its own adapter. Most DHL Express volume is international. Only 61% of SKUs in the catalog have an hs_code.

Why it bites DHL accepts a blank declaration at label time. The parcel is then held at customs for 5–9 days and the customer is billed a broker fee. The bug shows up in support tickets, not in logs.

Prompt fix

Evidence: customs/commercial-invoice.ts · carriers/canada-post.ts:112 · catalog query: 2,418 / 3,964 SKUs with hs_code

05 Landmine

Tracking ingest drops repeated status codes, and DHL repeats them at every hub

tracking/ingest.ts dedupes webhook events on (tracking_number, status_code) because UPS sometimes sends the same event twice. DHL sends a PU or AF code at each facility, and each one has a unique event_id.

Why it bites Only the first hub scan is kept, so orders show "Arrived at Leipzig hub" for a week while the parcel is already in Ohio. The estimated delivery date stops updating too.

Prompt fix

Evidence: tracking/ingest.ts:29 · DHL Unified Tracking API event model

06 Convention

Registering a carrier takes three steps, and only one is in the README

A carrier is live only when it is (1) exported from carriers/registry.ts, (2) seeded into carrier_accounts by a migration (the merchant settings page reads the table, not the registry), and (3) listed in __tests__/carrier-contract.spec.ts, which runs the shared suite for void, rate, label, and track.

Why it bites Without the migration, DHL compiles, passes tests, and never appears in any merchant's carrier list. Two people have lost an afternoon to this, according to #shipping-eng.

Prompt fix

Evidence: carriers/registry.ts · db/migrations/0071_seed_canada_post.sql · services/shipping/README.md

07 Convention

Carrier tests replay recorded cassettes, and CI blocks the network

Adapters are tested against HTTP cassettes in __cassettes__/<carrier>/. CI runs with nock.disableNetConnect(), so any un-recorded request fails. To record cassettes you need sandbox credentials from vault, which you'll have to request in #platform-access.

Why it bites Tests pass locally (your laptop has network) and fail in CI with a vague "Nock: No match for request". The usual workaround of hand-written mocks is rejected in review.

Prompt fix

Evidence: jest.setup.ts:4 · scripts/cassette-record.ts · CODEOWNERS (@acme/shipping-eng)
